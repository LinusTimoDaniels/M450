# Code Reviews

## Erkenntnisse

Bei guten Pull Requests nimmt sich der Reviewer Zeit, um den Code zu verstehen und zu überprüfen und nicht nur einfach kurz darüber zu schauen.

So sollten Pull Requests klein gehalten werden, heisst zwischen 200 und 400 Zeilen Code, dafür braucht der Reviewer zwischen 60 und 90 Minuten.

### Gute Pull Request Kommentare

- Zu viele oder zu wenige Code Comments, wobei weniger besser sind.
- Code Coverage, also Tests für den Code sind vorhanden. 
- Unnötiger und nicht verwendeter Code wird entfernt.
- Ist der Code lesbar (kein Spaghetti Code) und hat keine Typos.
- Hat es gutes Errorhandling und Logging.
